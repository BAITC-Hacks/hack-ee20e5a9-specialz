## Три примера объяснения роли

Выборка воспроизводима через `random.Random(42)` в `audit_project.py`:

- `100000008671929100`: terminal; один отправитель, нет получателей, depth=1. Первым сработало правило 3; это отсутствие выхода в выборке.
- `100000008691330100`: terminal; один отправитель, нет получателей, depth=1. Первым сработало правило 3.
- `100000008517538100`: coordinator; три отправителя, 17 получателей; BC≈0,000250 ≥ p95≈0,000158. Сработало правило 4, раньше правила распределителя.

Дополнительно проверены обработчики поиска для `100000000661912100`, `100000008346837100`, `100000002224132100`, переходы из топа, таблиц и SVG, неизвестный gid и изолированный узел. Для всех 444 узлов границы глубины есть оговорка об артефакте; для исходных клиентов не назначаются consolidator/transit по отношению сумм.

## Воспроизведение

```bash
python -m pip install -r requirements.txt
time python starter.py --data ./data --out ./out
python build_analyst_ui.py --data ./data --out ./out
python audit_project.py
node audit_ui.cjs
```

Node.js нужен только для дополнительной проверки UI на модели DOM. Открыть `out/analyst.html` можно напрямую как файл. Для ноутбука: выбрать ядро `.venv`, затем Run All. HTML не подключает внешние ресурсы; повторная генерация из текущего шаблона дала одинаковый SHA-256.

## Сохранность артефактов и ограничения

Три обязательных CSV после Run All и запуска CLI совпали побайтно с HEAD до аудита, а также с результатами чистого окружения. Их SHA-256:

```text
nodes_roles.csv  3ba9baa6598f41074d4c960fb399098226d587fe77750d53b3b2c79a67166ea0
clusters.csv     34e16dfffc0d755d94093679732a3a24d8738072617bc67bf84b8b8b6860eef4
top_nodes.csv    0fde5972493f01e5ae3580eeea9ff9e2ecc526dd260d27457703362a4bd54112
```

- Визуальный просмотр и проверка размеров в реальном браузере остаются ручным шагом перед демо. Проверка `audit_ui.cjs` не является браузерным тестом.
- SVG ограничена 12 крупнейшими связями каждого направления; все связи сохранены в таблицах. На узком экране схема прокручивается горизонтально.
- Роли и приоритеты — гипотезы, не вывод о виновности. Временное соседство не доказывает движение тех же денег; события одного дня не образуют пару.
- `sanity_check()` сравнивает только пары src/dst, не суммы и количества транзакций. Это явно указано в README.
- В Git не включаются `data/`, `.env`, `.venv` и исходные Parquet. Выданные данные разрешены ТЗ исключительно для использования в рамках хакатона. Снимок HTML содержит производные обезличенные данные и входит в запрошенные артефакты.
- Производительность на 1 млн узлов не проверена; README описывает необходимые изменения подхода. Зависимости заданы нижними границами, а не lock-файлом.
